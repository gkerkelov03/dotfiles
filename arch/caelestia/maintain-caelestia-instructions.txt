We use the full caelestia dots installer kind of just so we don't have to bother with manual
installing of the shell and cli and managing dependencies and maintaining reproducibility with our scripts when the repo keeps evolving so we are just gonna use the official caelestia installer which as of today is the caelestia install command of the cli which downloads all of hyprland and shell and every little tool it needs. This installer will give us many dotfiles that we don't want but we are just gonna delete them and make it so they don't appear again and thats how we are gonna reproduce our caelestia. The thing that makes the dotfiles that we don't need appear again and again is the cli because when it switches the theme it creates those folders and puts themes in them despite the fact we don't even use those apps, so we have to disable all the theming of apps that we don't want from the /dotfiles/config/caelestia/cli.json  

The last-used-reference files for cli.json and shell.json are here because currently they are listed only in the github readme of the cli and the shell as a plain text so this is the best 
versioning that i can do right now. Every once in a while we have to check the documentation to see if there are new options that we are interested in by comparing the current version of the reference files vs our last used version and we must put all the settings that we are interested in in our shell.json and cli.json files and we must not forget to change the last-used-reference files that we have saved.

When caelestia is installed it puts its dotfiles in .config/ so in our install-caelestia.sh script we first need to delete the folders that we don't want because after that when we symlink our own dotfiles it causes error "Such folder already exists". So we have to keep our dotfiles separate from theirs and every once in a while we have to take a look at the caelestia dots repo and check what have they changed and if we are interested in it we incorporate it in our own config manually. Thats why we are gonna keep commit hashes of the last referenced file versions and we are gonna keep our dotfiles separated from theirs and we are gonna manually merge what we want(it shouldn't be much). Also caelestia installs some tools that are listed in the manifest file under the tools component so we should delete the onces we don't want manually which our install-caelestia.sh script already does. Also we have to keep an eye on that list of tools because we want all the packages installed on our system to be in our packages file so we don't wanna have tools listed there that are installed but not in our packages file, those tools should either be uninstalled or listed in our packages file.

Caelestia also has an optional apps that it can install like discord spotify nvim and so on but we are not interested in any of that it only brings us wait time for the downloads it clutters our .config/ folder and gives us trouble with reproducing our dotfiles so we better install nvim ourselves instead of installing it as an optional tool from caelestia installer.
If there is a cool configuration for this tool that we need we merge it manually with our config and keep our configs separated.

We are gonna leave the btop config for them to maintain cuz they do a good job and we don't need to really change that config. Same goes for the hyprland config, we are just gonna use the hypr-user.lua and hypr-vars.lua files. As far as everything else goes:
